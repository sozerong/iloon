# ADR-0004. bulk 색인 건수·바이트 이중 제한

- 상태: Accepted
- 날짜: 2026-08
- 프로젝트: Illo-on

## 맥락

"건별 `index()` 를 bulk 로 바꾸자"로 시작했는데, 열어보니 **이미 `_bulk` 를 쓰고 있었다.**
실제 문제는 청킹이 없다는 것이었다 — 전체 문서를 요청 하나에 담는다.

문서 수를 올려가며 쟀다.

| 문서 수 | bulk 본문 | 결과 |
|---|---|---|
| 30,000 | 95.3 MB | 2.963s 성공 |
| 35,000 | 111 MB | **HTTP 413 — 0건 색인** |

OpenSearch `http.max_content_length` 기본값이 100MB 다.
이 선을 넘으면 **느려지는 게 아니라 한 건도 안 들어간다.**

## 검토한 선택지

1. **직접 리스트를 잘라 여러 번 POST** — 바이트 기준 분할과 부분 실패 파싱을 손으로 짜야 한다.
2. **`opensearch-py` 의 `helpers.bulk`** — 기존 코드가 전부 async 라 동기 버전을 쓰면
   이벤트 루프를 막는다.
3. **`helpers.async_bulk` + `AsyncOpenSearch` (채택)** — 같은 헬퍼의 비동기판.
   async 경로를 유지하면서 `chunk_size` / `max_chunk_bytes` / `raise_on_error=False` 를
   그대로 쓸 수 있다.

## 결정

- **건수와 바이트를 둘 다 제한한다.** 건수만 막으면 문서가 커질 때 같은 사고가 재발한다.
  `BULK_CHUNK_SIZE = 2000`, `BULK_MAX_CHUNK_BYTES = 10MB`.
- 적재 중 `refresh_interval="-1"`, **`try/finally` 로 복구 보장** 후 `_refresh` 1회 명시 호출.
  원래 값이 없었으면 `null` 로 되돌려 기본값 복원.
- 부분 실패를 `raise_on_error=False` 로 받아 일시적(429/502/503/504)과 영구로 분리.
  원인 타입별 건수를 로그로 남기고 일시적 실패만 1회 재시도.
  **HTTP 200 이어도 개별 항목은 실패할 수 있다**는 게 핵심이다.

`chunk_size` 는 실측으로 정했다 (20,000건 p50):

| chunk_size | 200 | 500 | 1,000 | 2,000 | 5,000 |
|---|---|---|---|---|---|
| p50 | 6.685s | 3.487s | 2.534s | **2.386s** | 2.362s |

2,000 이후 개선이 멈춰서 거기를 기본값으로 잡았다.

## 결과

| 문서 수 | before | after |
|---|---|---|
| 5,000 | 0.693s | 0.697s |
| 20,000 | 2.003s | 2.386s |
| 35,000 | **HTTP 413, 0건** | **5.444s, 35,000건** |
| 50,000 | **HTTP 413, 0건** | **5.656s, 50,000건** |

- **5,000건 규모에서는 개선이 없다.** 0.6% 는 회차 편차 안이다.
- **20,000건에서는 19% 느리다.** 왕복 횟수가 늘어난 대가다.
- 얻은 것은 속도가 아니라 **동작 범위**다. 30,000건에서 무너지던 상한이 사라졌다.

## 남은 일

재시도 1회뿐이다. 지속적인 429 에는 지수 백오프가 필요하다.
